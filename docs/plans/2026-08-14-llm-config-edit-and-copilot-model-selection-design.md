# LLM 配置修改与 Research Copilot 模型选择设计

日期：2026-08-14

## 背景

管理中心“系统与模型”的“LLM 大模型配置”目前支持新增、连接测试和删除，但没有明确的按配置 ID 修改能力。现有新增接口会按配置名称隐式覆盖同名记录，导致“新增”和“修改”的语义混合，改名时也无法稳定定位原配置。

Research Copilot 当前只检查项目是否存在 LLM 配置。Agent Run 执行时自动选取项目中最近更新且已启用的配置，用户不能在 Copilot 页面选择本次页面会话所使用的模型。

## 目标

1. 为已有 LLM 配置提供明确、安全的修改功能。
2. 允许用户在 Research Copilot 中选择一个已启用的项目 LLM 配置。
3. 模型选择仅在当前 Copilot 页面生命周期内保持，不修改项目全局默认配置，也不影响其他 Agent。
4. 保持未传模型配置 ID 的现有 Agent 调用兼容。

## 非目标

- 不新增数据库字段或迁移。
- 不改变其他 Agent 或工作区的模型选择交互。
- 不在浏览器持久化 Copilot 的模型选择。
- 不允许 Copilot 调用已停用的配置。
- 不向前端返回或回显明文 API Key。

## 已批准的产品决策

- Copilot 的选择在当前页面内保持，刷新页面或切换项目后重新初始化。
- 默认选择最近更新且已启用的配置。
- 修改配置时，API Key 留空表示保留原密钥；填写新值时才替换。
- Copilot 下拉框展示全部配置；未启用配置置灰且不可选。
- 使用稳定的配置 ID 贯穿前端、Agent Run 上下文和运行时解析。

## 后端设计

### LLM 配置接口

保留现有列表、连接测试和删除接口，拆分创建与修改语义：

- `POST /projects/{project_id}/settings/llm`：只创建新配置。
- `PATCH /projects/{project_id}/settings/llm/{config_id}`：按 ID 修改已有配置。

两个写接口均要求项目管理员权限。修改接口先验证配置存在且属于当前项目，随后更新名称、供应商类型、Base URL、模型、启用状态和描述。

修改请求中的 `api_key` 为空字符串时不触碰数据库中的现有密钥；非空时先加密再替换。响应继续只返回掩码。

列表接口按 `updated_at DESC, id` 确定性排序。这样前端可以选择返回结果中的第一个启用配置，并与当前运行时“最近更新且启用”的默认行为保持一致，无需在响应中新增时间字段。

### Agent Run 上下文

在 `AgentRunContext` 中新增可选的 `llm_config_id: UUID`。该值随已有 `input_json.context` 持久化，因此不需要数据库迁移，并可在历史运行中追踪实际选择。

Research Copilot 创建 research Agent Run 时传入当前选中的配置 ID。其他调用方无需修改；未传该字段时继续使用原有默认解析规则。

### 模型解析

扩展 LLM provider factory，使其能够接收可选配置 ID：

- 未传配置 ID：按现有规则选取最近更新且已启用的项目配置，再按环境变量和 mock provider 回退。
- 传入配置 ID：只按 ID 查找，并验证配置属于运行对应项目且处于启用状态。

显式选择失败时不回退到其他模型，以避免用户选择与实际调用不一致。配置不存在、跨项目或已停用均产生明确的应用错误，由 Agent Runtime 记录为失败运行。

配置在 Run 排队之后被删除或停用时采用同一规则：该 Run 明确失败，不静默切换模型。

## 前端设计

### 管理中心配置修改

每条配置的操作区新增“修改”按钮。点击后复用现有表单组件，并预填：

- 配置名称
- 供应商类型
- Base URL
- 模型名称
- 启用状态
- 描述

API Key 不预填，并显示“留空则保留当前密钥”的提示。编辑提交调用新的 PATCH 接口；新增继续调用 POST 接口。表单通过明确标题和按钮文字区分“添加配置”与“修改配置”。取消编辑时关闭表单并清除编辑状态。

表单加入启用状态控制，使用户能够停用或重新启用配置。保存成功后刷新 `['llm-configs', projectId]` 查询缓存。

### Research Copilot 模型选择器

在消息输入区域上方增加模型下拉框，选项主文案为“配置名称 · 模型名称”。全部配置均展示，未启用项带状态标识、置灰且不可选择。

初始化规则：

1. 配置列表加载完成后，选择列表中第一个启用配置。
2. 用户手动切换后，在当前组件生命周期内保持该选择。
3. 普通查询刷新不覆盖仍然有效的用户选择。
4. 如果当前配置被删除或停用，则回退到最新启用配置。
5. 如果没有启用配置，则清空选择、禁用发送，并提示前往“管理中心 → 系统与模型”添加或启用配置。

发送消息时将选中的配置 ID 合并到 seed 生成的既有 context 中，确保论文、章节或 idea 上下文不会被覆盖。

当前用于显示 mock 警告的判断应改为“是否存在启用配置”，而不是“配置列表是否非空”。

## 错误处理

- 修改不存在或跨项目配置：返回未找到错误，避免暴露其他项目资源是否存在。
- 非管理员修改：沿用项目角色权限错误。
- Copilot 显式选择无效：Agent Run 失败信息说明配置不存在、跨项目或已停用。
- 没有启用配置：前端在提交前阻止发送，并给出配置入口提示。
- 网络或保存失败：保留表单内容并显示现有 API 错误信息，不关闭编辑表单。

## 测试策略

### 后端

- POST 创建同名配置时不覆盖既有记录。
- 管理员可按 ID 修改配置，非管理员被拒绝。
- 修改时空 API Key 保留原密钥，新 API Key 被加密替换。
- 不可修改其他项目或不存在的配置。
- Agent Run 接受并保存 `llm_config_id`。
- Runtime 使用指定项目配置。
- 指定配置不存在、跨项目或未启用时运行失败。
- 未指定配置 ID 时保持原有默认选择和回退行为。

### 前端

- 修改按钮打开并预填非敏感字段。
- API Key 不回显，留空时允许保存。
- 新增与修改调用不同接口。
- Copilot 默认选择最新启用配置。
- 未启用配置可见但不可选择。
- 页面内切换后，后续请求携带所选 `llm_config_id`。
- 配置刷新不会覆盖有效的手动选择。
- 当前选择失效时正确回退。
- 无启用配置时禁用发送并显示引导。

### 联调

在本地项目中验证“添加配置 → 修改配置 → Copilot 选择配置 → 发起对话”的完整流程。真实模型只执行一次最小调用，避免重复消耗。

## 兼容性与安全性

- `llm_config_id` 为可选字段，现有 Agent 调用无需同步改造。
- API Key 继续加密存储，只返回掩码。
- 服务端不信任前端选项状态，运行时再次校验项目归属和启用状态。
- 使用配置 ID 而非名称，避免重名、改名或并发操作导致错误路由。
- 不修改数据库结构，不引入迁移风险。
